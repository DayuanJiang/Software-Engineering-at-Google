## 术语与语义

| 英文 | 本章处理 |
| --- | --- |
| false negative | 漏报：确有工具旨在发现的问题，却未检出。 |
| false positive | 误报：代码没有该问题，却被工具标记为有问题。 |
| effective false positive | 感知误报，首次保留英文。依原文定义，以开发者看到报告后是否采取积极行动衡量，不等同于技术上的误报，也不表示误报“有效”。 |
| effective false-positive rate | 感知误报率；Tricorder 检查门槛低于10%、总体略低于5%、编译器检查不得产生感知误报，三处各自的限定不变。 |
| analysis / analyzer / result | 分别按语境使用分析、分析器、分析结果；结果指出的问题不是分析器自身的缺陷，修复代码也不是修复报告本身。 |
| check / compiler check | 检查项／编译器检查；与具体工具、报告的问题及修复方案区分。 |
| static / dynamic analysis | 静态／动态分析，区分分析源代码和运行中的程序。 |
| intraprocedural / interprocedural | 过程内／过程间分析，不译为面向过程；保留组合式、增量式分析及基础设施投入的条件。 |
| code review / infrastructure | 代码审查／基础设施。 |
| Refaster / Error Prone / Critique / IfThisThenThat | 保留工具专名；修正 Refaster 被译为“重构”、Error Prone 被译为“容易出错”，以及 IfThisThenThat 的拼写。 |
| dead code / style / presubmit | 死代码／代码风格／预提交检查；不混为硬编码、页面样式或提交动作。 |
