## 术语与主要修正

| 项目 | 本章处理 |
| --- | --- |
| CI / CB / CT / CD | 分别为持续集成、持续构建、持续测试、持续交付；Continuous Deployment 明确译为持续部署。CI 不等同于测试，CT 贯穿构建与交付。 |
| presubmit / post-submit / postsubmit | 提交前测试／提交后测试；不再用容易误解为提交操作的“预提交”“后提交”。 |
| true head / green head | 保留标识符，解释为已提交的最新变更／CB 已验证通过的最新变更；cut 指取用代码版本，不是切割；promote 指推进到后续环境，不是软件升级。 |
| release candidate / staging | 候选发布版本（RC）／预发布环境；与临时沙盒、开发和生产环境区分。 |
| deterministic / flaky / brittle | 确定性／不稳定、偶发失败／脆弱；明确相同代码重跑的结果一致性，与对无害变更敏感不是同一概念。 |
| hermetic / isolation / fake | 封闭／隔离性／伪实现（fake）；不译作隐秘、密封或泛泛的模拟。保留系统时间、随机数、竞态条件仍会影响确定性的限制。 |
| size / scope / fidelity | 测试规模／测试范围／仿真度；小型测试与单元测试不强行等同，也不把所有大范围测试改叫大型测试。 |
| culprit finding / rollback | 定位致错变更／回滚；二分查找不是二进制搜索，回滚操作不与回归缺陷混同。 |
| error budget / invariant / page | 错误预算／不变量／呼叫值班人员；修正“错误成本”“不变因素”“生成页面”。 |
| record/replay / cherry-pick | 录制／重放；拣选提交并保留 cherry-pick，纠正“偷梁换柱”。 |
