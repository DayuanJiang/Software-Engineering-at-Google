## 术语与实质修正

- `deprecation` 统一为“弃用”；本章定义包含有序迁出及最终移除。`deprecated` 状态使用“已弃用”“标记为已弃用”等，不等同于已经删除；`migration` 为“迁移”，`removal` 为“移除”，关闭、停用和核电站退役按各自语境区分。
- `advisory / compulsory deprecation` 为“建议性弃用／强制性弃用”；`backsliding` 指不断新增对旧系统的使用，不是重新启动已经移除的系统，也不是回滚。
- 采用“基础设施”“单体代码仓库”“代码审查”“全局测试套件”“符号”“编译器注解”“可见性白名单”“可操作性”“相关性”“警报疲劳”；保留 Kythe、Tricorder、ErrorProne、clang-tidy、Java、@deprecated 等标识。
- 19、23行：纠正“弃用收益并非微不足道”的反向理解，以及把弃用处理不当译为“不推荐使用”；恢复软件栈与函数调用的范围。
- 31、66、70行：恢复内部 API 用户可能自认最终用户、负责人能了解使用情况的边界；区分碰巧可用与保证可用，补回每一种旧用法均须评估。

- 154、168、172行：纠正“只发警告就不管”被译成建议的问题；恢复调整时间表的可能、充分告知后执行移除的权限，以及专门团队持续投入到完成的要求。
