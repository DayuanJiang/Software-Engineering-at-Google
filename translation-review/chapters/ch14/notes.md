## 术语与语义边界

| 英文 | 本章处理 |
| --- | --- |
| larger tests / large tests | 前者一般译“较大规模测试”，包括不受小型测试约束的测试；后者译“大型测试”。标题改为“较大规模测试”，不把全部较大规模测试都归为正式的 large 级别。 |
| test size / test scope | 测试规模／测试范围。前者涉及运行资源与限制，后者涉及被验证代码和系统的范围。单进程、单机、多机的运行分类与 SUT 覆盖范围分别表述；拆成“较小测试”不等于必然满足 small 级别。 |
| hermeticity / hermetic | 封闭性／封闭，必要时写明隔离含义。指与当前测试之外的使用及交互隔离，不是物理密封，也不等于小型或单机。保留多机不稳定因素与单机封闭环境的具体区别。 |
| fidelity | 仿真度，分别说明环境与测试内容接近真实系统的程度；不等于覆盖率。 |
| test double / fake / stub / mock | 测试替身／伪实现／桩／模拟对象。第78、86行首次明确具体类型，避免把团队提供的 fake 写成 mock。 |
| flaky / brittle | 结果不稳定／脆弱。前者是非确定性失败，后者是无害的 UI 或代码变更引发测试失败，不合并。 |
| regression / rollback | 回归缺陷／回滚。差异“回归测试”保留测试类型名称，性能语境用“性能退化”或“性能回归缺陷”。 |
| A/B diff / user experimentation | A/B 差异比较用于核查版本行为；用户实验比较实验组与对照组。两者不混作同一种测试目的。 |
| seeded data / multiplexed production data | 预置数据／复制分发的生产流量，不写成抽象的“种子工作”或网络多路传输。 |
| emergent behavior / sublinear | 涌现行为／次线性；分别保留整体行为与成本增长关系。 |
| ownership / presubmit / post-submit | 责任归属／提交前／提交后。OWNERS 保留为专名，monorepo 译为“单体代码仓库”。 |
| continuous delivery / disaster recovery | 持续交付／灾难恢复，不改成持续部署或普通故障恢复。 |
