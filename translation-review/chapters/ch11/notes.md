## 术语选择

| 英文 | 本章用法与边界 |
| --- | --- |
| test size | 测试规模，指运行资源、允许操作和运行约束；small/medium/large 为小型/中型/大型测试，不按代码行数定义。 |
| test scope | 测试范围，指要验证的代码范围；narrow/medium/broad 为范围较窄/中等范围/范围较广，不与规模混用。 |
| flaky / flake | 不稳定测试／非确定性失败；flaky rate 为非确定性失败率，不译为松散、片状或普通故障率。 |
| brittle | 脆弱测试／脆弱性，强调无关代码变更也可能使测试失败，不与 flaky 混同。 |
| test double | 测试替身；具体类型保留 fake、mock、stub，避免把上位概念或 faking 一律译成模拟。 |
| hermetic | 封闭、自足，或与外部环境隔离；结合环境准备、执行和清理来说明，不译作物理密封。 |
| code coverage | 代码覆盖率，记录执行情况，不等于验证正确；提要的 test coverage 保留为“测试覆盖”，不擅自变成单一指标。 |
| regression / rollback | 回归缺陷／回滚，分别指问题和操作。 |
| monorepo / repository branch | 单体代码仓库／代码仓库分支，不译成单版本库。 |
| code review / infrastructure / CI | 代码审查／基础设施／持续集成。 |
| Orientation Classes / TotT | 入职培训课程／厕所里的测试专栏；TotT 的 episode 为“期”，不是“剧集”。 |
| Project Health (pH) | 保留工具专名和大小写，按项目健康状况评分理解，不解释为酸碱度。 |
