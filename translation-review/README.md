# 翻译润色记录

本目录包含准备阶段的分析快照，以及全书中文润色的审阅记录。
第1至25章及序言、前言、后记的现有中文均已审校。英文源文、程序代码和图片保留；
目录只同步章节名称，另有一处损坏链接语法及明确登记的中文引文例外。

文本策略：信息型、偏硬技术书籍，润色自由度约 3/10，准确性优先。
术语抽取与统计是本次任务补充的实施方法，不是 `en-zh-translation-polish` skill 自带的脚本。

## 方法与边界

1. 使用 `markdown-it-py` 解析 `zh-cn/` 的全部 Markdown，不以正则表达式代替 Markdown 结构解析。
2. 按段落、列表、表格、标题、引用等结构提取语言片段。英文段落中的行内代码标识符保留，围栏与缩进代码块不进入 NLP。
3. 中文字符识别只用于提出语言划分候选，不代表语义判定。混合标题按中英文前后分开；同一行中文正文内的英文不重复计入英文语料。
4. 英文连续块后紧跟中文连续块时提出配对。单块对应标为 `adjacent_1_to_1`；数量及类型一致的连续块标为 `ordered_run`。不确定的组标为 `ambiguous`，没有后续译文候选的英文标为 `unpaired`。这些状态均不是人工确认的翻译对齐。
5. 使用 spaCy `en_core_web_sm` 做分词、词形还原、词性和依存分析，提取名词、名词短语、复合词组、`of` 短语、缩写和部分专名。名词单复数归一，形容词和不同概念不合并。
6. 收集每个候选在抽取阶段实际出现过的单复数等表面形式，再带单词边界回扫全部英文片段。计数不再依赖该处的词性标签，可覆盖标题和脚注边界。尚未被模型发现的其他词形不会凭空扩展。相同位置的同一术语只计一次，重叠的不同候选分别计数。
7. 保留频次至少为 2，或出现在标题，或带有缩写、专名、定义句信号的候选。低频普通名词短语可能被过滤；这不是完整术语识别器。
8. 使用 jieba 的精确分词、HMM 和词性标注，从中文中抽取词和短语；否定前缀保留，不把“不稳定测试”误截为“稳定测试”。不注入已审定术语作自定义词典，避免反过来影响初始统计。
9. 只使用非歧义候选对齐组计算中英共现，按 Dice 系数排序。共现的高分词仍可能不是译法，例如两个不同概念在同段被比较。自动候选一律标为未审定。
10. 人工结合候选频次和原书定义选择核心术语，再记录已有异译、首选译法及例外。频次最高的译法不一定正确。

候选优先级是可解释的启发式分数，不是术语正确率：

```text
log(1 + 英文频次) * (1 + log(1 + 文档数)) + 2 * log(1 + 标题频次)
```

### 如何理解计数

- 英文频次包括正文、标题、引文、脚注、表格和图注的抽取命中；检测到的署名与代码块排除。
- 行内 API 名称等保留在英文上下文中；英文代码示例不反复推高词频。
- 同一句在不同正文位置再次出现仍分别计数，不以整句去重抹掉真实重复。
- 文档数包括序言、前言和后记；正文章节数只计算 25 章。
- 候选发现、词形归组和语言识别依赖模型及启发式规则；频次是已观察词形在清理后英文片段中的词边界命中数，不等于概念义项频次。模型可能把同一概念提名为两个候选，人工审定时须检查，不能直接相加。
- `glossary.md` 中的已有异译计数，是候选对齐中文段内的精确字符串命中。它不是逐词翻译对齐结果。例如 Critique 段落里的“评论”也可能是正确翻译的 comment。
- 未对齐、歧义组和未列入别名表的译法不会进入已有异译命中数；未命中不等于漏译。
- CI/CD 等全称与缩写没有自动合并；正式术语表注明各条计数所用的 `keys`。

## 数据文件

以下全书统计仍是润色前的准备阶段快照，不代表润色后的中文词频。
原始章节可由 `baseline.json` 记录的 Git 提交还原（仓库历史在 2026 年 9 月 21 日为移除大文件重写过一次，该提交的哈希由 `679725c` 变为 `110720f`，内容相同，标签 `translation-baseline` 指向它）；新增术语和适用边界保存在各章 `notes.md` 及第一章术语补充中。

| 文件 | 用途 |
| --- | --- |
| `baseline.json` | 修改前的 Git 提交、文件及图片哈希、英文、代码、链接、脚注和结构基线 |
| `segments.jsonl` | 可回查的语言片段、短 ID、文件和行号；表格位置可能是所在行的位置。体积较大，未纳入版本库，可按下文命令重新生成 |
| `alignments.json` | 候选中英配对及歧义状态 |
| `candidates.json` | 全部保留候选、逐文档与文本类型计数、实际表面形式、每次命中的片段和字符偏移。体积较大，未纳入版本库，可按下文命令重新生成 |
| `chinese-frequency.json` | 中文候选词及短语的实际抽取次数 |
| `glossary-decisions.json` | 人工维护的首选译法、适用范围、别名和原文证据，是术语审定的唯一编辑入口 |
| `glossary-statistics.json` | 根据审定文件生成的计数、异译位置和自动核对过的证据位置 |
| `existing-issues.json` | 自动检查发现的既有引用和标记问题，保留证据状态 |
| `summary.json` | 输入文件哈希、工具代码哈希、包版本和统计摘要 |

片段 ID 示例为 `ch12:s0006`。它是当前快照内的索引，不承诺在正文重新分段后保持不变。
行号和字符偏移指向对应快照，需与 `summary.json` 中的输入哈希一起使用。

## 用 uv 复现

在仓库根目录运行。依赖定义及锁文件位于 `tools/`，环境位于 `tools/.venv/`，
与书籍站点及系统 Python 隔离。首次同步需要网络；后续分析只读本地语料，不上传书籍内容。

```bash
uv sync --project tools --locked --python 3.12 --cache-dir .cache/uv

uv run --offline --locked --project tools --cache-dir .cache/uv python tools/book_review.py verify --final
uv run --offline --locked --project tools --cache-dir .cache/uv python -m unittest discover -s tools -p 'test_*.py' -v
```

`segments.jsonl` 和 `candidates.json` 合计约 20 MB，不再随仓库分发。需要时先检出 `baseline.json` 记录的提交，运行下面的 `analyze` 命令即可得到与准备阶段一致的快照。

如需重新统计当前内容，使用新目录保留准备阶段快照：

```bash
uv run --offline --locked --project tools --cache-dir .cache/uv python tools/translation_audit.py analyze --out .cache/current-translation-analysis
```

`analyze` 会重建统计结果，不会改动正文或覆盖 `baseline.json`、人工术语决定和问题说明。
`glossary` 重建展示文档，不改人工审定文件。

基线已经生成。`baseline` 命令拒绝覆盖已有基线；只有确实要开始一个新基线时才指定新的 `--out`：

```bash
uv run --offline --locked --project tools --cache-dir .cache/uv python tools/translation_audit.py baseline --out .cache/new-translation-baseline
```

`verify --exact` 要求全部被记录的书籍、站点和图片文件逐字节不变，适用于准备阶段。
正文开始润色后，不带 `--exact` 的 `verify` 检查保护内容；标题、HTML 或结构的有意修改仍会报出，必须人工核对，不能直接重建基线消掉差异。
有几处缩进中文引文已登记为非程序代码的修改例外，一处原损坏链接已登记语法修复。
当前全书使用 `book_review.py verify --final` 校验，它只接受具体登记的前后内容，不会忽略任意代码或链接差异。
如仅检查第一章，可运行 `chapter_pilot.py verify --chapter-only`。
英文混在中文句内的自由文本仍需检查 diff，基线不是语义正确性的证明。

依赖说明：固定 `setuptools` 以兼容 jieba 的 `pkg_resources` 导入；显式固定 `click`，
因为所用 spaCy 版本会直接导入它。运行时的依赖弃用警告不影响测试结果，后续升级需重新执行测试。
